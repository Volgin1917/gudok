# Переход на выделенный сервер: конфигурация и план «полноценного сервиса»

> Статус: **решения по ключевым пунктам приняты** · 15.09.2026 · автор: рабочая сессия
> Решено (15.09.2026): РФ-VPS уровня «Минимум» (~400–500 ₽/мес, 1 vCPU / 2 ГБ + swap / 40–50 ГБ NVMe);
> GitHub Pages остаётся зеркалом последней сборки (gh-pages force-update, main — только код);
> локальный LLM — вне горизонта; очередь этапа B1 — по §6 (поиск → сжатие фото → метрики читателей → TG-уведомления).
> Открыты: конкретный провайдер/тариф, имя домена, частота сбора (§10). План внесён в ROADMAP (инфраструктурный трек).

## 1. Диагноз: во что сегодня упирается GitHub Pages

| Ограничение | Текущая цена (факты на 15.09.2026) | Что снимает сервер |
|---|---|---|
| **Git как файловое хранилище** | Зеркала фото +3–6 МБ/день; `assets/photos` уже 67 МБ (535 файлов, ср. 128 КБ), `.git` — 75 МБ, всё дерево — 149 МБ. Открытый вопрос ROADMAP «политика хранения зеркал» не решаем в принципе: любой ответ упирается в то, что файл публикуется через коммит | Зеркала живут на диске, git хранит только код (~10 МБ). Вопрос закрывается сам |
| **Публикация = git push + сборка Pages** | ~6 мин на прогон (было 12,5 при грязном дереве), гонки параллельных сессий, `ci_push.sh` с rebase/reset/ретраями, токен в CI (PAT уже компрометировался — урок) | Публикация = копирование в webroot, секунды, атомарно (symlink-swap). Гонок нет: один таймер, одна очередь systemd |
| **Ноль видимости читателей** | Ни метрик, ни логов. Ось «аудитория» в «Инфопространстве» строится по данным источников (охваты TG), а не по нашим читателям | Логи nginx → своя метрика: кто, что, когда читает. Первая настоящая обратная связь с аудиторией |
| **Нет динамического слоя** | Нет поиска по архиву, нет формы обратной связи, «конвейер редакции» (пункт плана со статусом «готовы») некуда встроить; калибровка агентности (~200 сообщений вручную) — через файлы | Полнотекстовый поиск (SQLite FTS5 — **stdlib**), веб-панель разметки, загрузка данных (ЕИС CSV, ключ VK) формами вместо «ждём файл от пользователя» |
| **Сбор из-за рубежа** | GitHub Actions = IP Azure (США/ЕС). t.me/s, VK, Госвеб могут троттлить зарубежные дата-центры; часть отказов в `fetch_status` может быть географией, а не смертью источника | Сбор из РФ, близко к источникам. Побочно: VK API и gosuslugi.ru отвечают стабильнее |
| **Частота сбора = 1 раз/сутки** | Латентность «событие → публикация» и каскады считаются по суточному срезу; внутридневная динамика теряется | Таймер раз в 2–3 ч: каскады видны в реальном времени, «полка сюжета» точнеет |
| **Зависимость от платформы** | Доступность и политика github.io/Pages вне контроля; секреты (VK_TOKEN) на чужой стороне | Свой контур: секреты в `/etc/gudok/*.env` (chmod 600), резервная копия сайта — у себя |

**Что НЕ является проблемой Pages** (честности ради): автономность HTML, stdlib-ядро, вежливость к источникам, UTC+4 — это принципы проекта, они переносятся на сервер без изменений.

## 2. Целевая архитектура

```
 источники (RSS · TG · VK · Госвеб)
        │  сбор из РФ, таймер: 07:30 + внутридневные снапшоты (опц.)
        ▼
 ┌──────────────────────────── VPS ────────────────────────────┐
 │ systemd timers: gudok-daily / weekly / monthly              │
 │   └─ run.sh: collect → enrich → photos(+Pillow) → dedup     │
 │              → trends → analytics → generate                │
 │                                                             │
 │ /srv/gudok/           код (git pull) + data/ + зеркала фото │
 │   ├─ data/search.db   SQLite FTS5 — поиск по архиву (stdlib)│
 │   └─ build/ → rsync → /var/www/gudok (атомарный symlink)    │
 │                                                             │
 │ nginx: HTTPS (Let's Encrypt), кэш статики, access-логи      │
 │   ├─ /            статический сайт (как сейчас)             │
 │   ├─ /api/        WSGI (waitress): поиск, статус, панель    │
 │   └─ логи → метрика «читатели» (парсер stdlib)              │
 │                                                             │
 │ notify.py → Telegram-канал (анонс выпуска)                  │
 │ restic → S3 (ежедневный бэкап data/, зеркал, конфигов)      │
 │ мониторинг: OnFailure→TG, /healthz, опц. Uptime Kuma        │
 └─────────────────────────────────────────────────────────────┘
        │
        ▼ резерв
 GitHub Pages-зеркало (gh-pages = снапшот последней сборки,
 force-update раз в сутки; main-ветка = только код)
```

Принцип сохраняется: **ядро — только stdlib**. Серверные надстройки (Pillow, waitress) — опциональный слой через `try/except ImportError`, все 188 тестов зелёные и без них (проверяется в CI на чистом Python).

## 3. Конфигурация сервера: три уровня

Расчёт нагрузки (фактические замеры): пик конвейера — Python ~200–300 МБ RAM; nginx ~20 МБ; панель/API ~100 МБ; диск: база ~200 МБ/год (jsonl) + FTS5-индекс + зеркала после сжатия ~0,4–0,7 ГБ/год.

| Уровень | Железо | Цена (РФ, 2026) | Хватает на |
|---|---|---|---|
| **Минимум — ✅ выбран (15.09.2026)** | 1 vCPU, 2 ГБ RAM (+2 ГБ swap), 40–50 ГБ NVMe | ~300–500 ₽/мес (Beget, FirstVDS, Aeza); Timeweb Cloud 2CPU/2GB — ~900 ₽/мес | Всё из §6 кроме локального LLM и self-hosted Matomo. Панель (waitress ~100 МБ) и PDF (последовательно, пик ~300 МБ) влезают в 2 ГБ при разнесении таймеров; вместо Uptime Kuma — systemd `OnFailure=` → алерт в TG |
| **Оптимум (резерв роста)** | 2 vCPU, 4 ГБ RAM, 60–80 ГБ NVMe | ~1 080–1 500 ₽/мес (Timeweb Cloud 2CPU/4GB/50GB — 1 080 ₽; 4CPU/8GB — 1 800 ₽) | Запас под Matomo/Uptime Kuma, частые снапшоты, рост трафика |
| **С локальным LLM** | 4–8 vCPU, 16–32 ГБ RAM, 100+ ГБ | ~3 500–6 000 ₽/мес | Ollama + 7–8B q4 (~6–8 ГБ RAM): саммаризация, NER, «natasha без natasha». Принцип «без внешних API» сохраняется — модель локальная |

Дисциплина 2 ГБ (плата за «Минимум»): swap 2 ГБ (zram или диск), таймеры разнести (daily 07:30, внутридневные снапшоты — :15, чтобы не пересекаться с панелью/логами), `MemoryHigh=` у юнитов конвейера; при росте — resize у провайдера 2→4 ГБ обычно без переезда (простой ~10 мин), конфигурация «Оптимум» того же плана.

ОС: **Ubuntu 24.04 LTS** (или Debian 12). Диск 50 ГБ = 3–5 лет роста без чистки; 80 ГБ — с запасом на бэкап-снапшоты.

Локация/провайдер — точка выбора (§10):
- **РФ-провайдер** (Timeweb Cloud, Beget, Selectel, FirstVDS, Aeza): оплата картой РФ, низкая задержка до читателей и источников, соответствие 152-ФЗ при сборе персданных. Минус: дороже западных на сопоставимом железе.
- **Зарубежный** (Hetzner ~€4–6/мес, OVH): дешевле/качественнее, но оплата из РФ — квест, и сбор TG/VK с зарубежного IP возвращает проблему, от которой уходим.
- Шаред-хостинг (~250 ₽/мес) не подходит: нет root/systemd/долгоживущих процессов — панель и бот не встанут.

## 4. Софт

База (этап A, всё — пакеты дистрибутива):
- `nginx` + `certbot` (Let's Encrypt; без домена HTTPS не оформить — домен фактически обязателен)
- `python3.11+` (stdlib-ядро проекта; на сервере доступны sqlite3 с FTS5, wsgiref, venv)
- `systemd` timers: `gudok-daily.timer` (OnCalendar=*-*-* 07:30 Europe/Ulyanovsk — `timedatectl set-timezone`), weekly, monthly; `Persistent=true` (догон пропущенного после downtime)
- `restic` → S3-совместимое хранилище (Timeweb S3 / Yandex Object Storage, ~50–150 ₽/мес за 25 ГБ): `data/`, зеркала фото (**критично** — TG CDN истекает, зеркало неповторимо), `/etc/gudok/`, конфиг nginx
- Hardening: `ufw` (22/80/443), `fail2ban`, SSH только по ключам, `unattended-upgrades`, секреты — env-файлы вне репозитория

Опциональный слой (этап B, pip в venv, guarded import):
- `Pillow` — сжатие/ресайз/WebP зеркал (закрывает открытый вопрос ROADMAP)
- `waitress` — WSGI-сервер для `/api` и панели (чистый Python; альтернатива — stdlib `wsgiref` для низкой нагрузки)
- позже: `weasyprint` (PDF-печать выпуска), Ollama (LLM)

## 6. Что становится возможным для «полноценного сервиса»

Приоритет = ценность для редакции; трудозатраты: S ≤ 1 день, M 2–5 дней, L 1–2 недели.

1. **Полнотекстовый поиск по архиву** (FTS5, stdlib) — S. Сейчас архив = календарь выпусков; найти «где писали про тарифы ЖКХ в мае» нельзя.
2. **Сжатие фото** (Pillow) — S. Закрывает открытый вопрос ROADMAP; страницы грузятся в 2–3 раза быстрее на мобильном.
3. **Метрики читателей** — S. Впервые видим свою аудиторию, а не только аудиторию источников. Кандидат в «паспорт метрики» оси «аудитория».
4. **TG-уведомление о выпуске** — S. «Доставка через Telegram» была отложена из-за автономного контура — на сервере контур свой.
5. **Внутридневной сбор** — M. Латентность и каскады из суточного среза становятся реальным временем; +«свежесть» витрины.
6. **Конвейер редакции (веб-панель)** — M. Разметка агентности, верификация источников, приём данных (ЕИС, VK-ключ) — всё, что сейчас «ждём файл от пользователя», становится формой с кнопкой.
7. **RSS/Atom-фиды выпуска и рубрик** — S. Нас смогут читать агрегаторы.
8. **PDF-версия для печати** (weasyprint) — M. `print_*.html` → готовый PDF в один клик, можно рассылать по организациям.
9. **Email-рассылка дайджеста** — M. Технически просто (SMTP), юридически — 152-ФЗ: локализация баз, уведомление РКН как оператор персданных. Проще остаться в Telegram.
10. **Локальный LLM** (Ollama 7–8B q4) — L, требует уровень 3 (§3). Саммаризация длинных текстов, извлечение сущностей/дат (латентность без эвристик), «словарь власти» → полноценный стилометрический слой. Внешних API нет — принцип не нарушен.
11. **Независимый архив инфополя региона** — уже почти есть (полные тексты в enrich, зеркала), но на сервере становится вечным: свой диск + бэкапы, истечение TG CDN больше не угроза.
12. **Комментарийный слой / форма сигнала от читателей** — M. Технически возможен; решение — за редакцией (этика d3, «немые группы» могут стать «слышимыми»: житель пишет — мы проверяем и вводим в оборот).
13. **Электоральный коллектор и цифровой скрининг протоколов** — M. Архив ИКУО + ГАС «Выборы»; на stdlib: закон Бенфорда (первая цифра), последние цифры процентов и голосов, целые проценты, корреляция «недействительные бюллетени × явка», диаграмма Шпилькина (явка × результат); формальное p-значение и регрессионный разрез — с внешними библиотеками (опционально). Наполняет проект «Выборы» (М-37…М-41).

## 9. Риски

- **Единая точка отказа.** VPS упал — сайт недоступен. Митигация: Pages-зеркало (актуальность ≤ 24 ч), `Persistent=true` у таймеров (догон после downtime), мониторинг с алертом в TG.
- **Безопасность.** Публичный сервер — цель. Чеклист этапа 0: ключи SSH, ufw, fail2ban, автопатчи, секреты вне git (урок с PAT), панель под авторизацией, nginx без server_tokens.
- **Юридическое (кратко, вне техплана).** Домен .ru — реальные данные регистратора; сбор email/комментариев — 152-ФЗ (локализация, уведомление РКН); статус СМИ — по закону о СМИ регистрация необязательна, но у редакции должно быть решение о позиционировании. Провайдер РФ снимает вопросы локализации; зарубежный — добавляет.
- **Двойной контур на переходный период.** Сервер и CI могут разойтись (версии кода). Правило этапа A: сервер — только `git pull` из main, никаких локальных правок; CI — только тесты и зеркало.
- **Потеря зеркал при бэкап-инциденте.** Зеркала TG-фото неповторимы (CDN истекает) — они в бэкапе первой категории, восстановление бэкапа проверяется на этапе 0 (не «настроен restic», а «восстановили тестовый файл»).

## 10. Точки выбора

**Решено (редакцией, 15.09.2026):**

1. **Провайдер и бюджет**: РФ-VPS, уровень «Минимум» — 1 vCPU / 2 ГБ RAM + 2 ГБ swap / 40–50 ГБ NVMe, Ubuntu 24.04, ~300–500 ₽/мес (кандидаты: Beget, FirstVDS, Aeza; Timeweb Cloud — если «минимум» окажется сопоставим по цене). LLM-запас не закладываем; при росте — resize 2→4 ГБ у того же провайдера.
2. **GitHub Pages**: остаётся зеркалом — `gh-pages` = снапшот последней сборки (force-update раз в сутки, история не растёт), `main` — только код. Откат при падении VPS — возврат DNS за минуты.
3. **Локальный LLM**: вне горизонта — эвристики и словари остаются ядром; возврат к вопросу после апгрейда железа или на отдельной машине.
4. **Очередь этапа B1**: по §6 — поиск по архиву (SQLite FTS5) → сжатие фото (Pillow, закрытие вопроса о зеркалах) → метрики читателей (логи nginx) → TG-уведомление выпуска.
