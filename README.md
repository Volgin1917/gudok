# Гудок — информационно-аналитический листок марксистской группы «Победа» по Ульяновской области

**🌐 Сайт: https://volgin1917.github.io/gudok/** · обновляется автоматически ежедневно в 07:30 (UTC+4) через GitHub Actions

Автоматизированный конвейер ежедневных дайджестов с трекером тенденций
информационной повестки. **Только стандартная библиотека Python 3.8+ — никаких зависимостей.**

```
сбор (RSS+TG+VK+сайты ОМСУ) → обогащение → дедупликация → тренды → HTML-выпуск + витрина
  collector.py      enrich.py          dedup.py   trends.py+analytics   generate.py
```

Фаза 2 (`analytics.py`, вызывается автоматически из `trends.py` → `data/analytics.json`):
* **Автоафиша** — извлечение дат, диапазонов, времени и площадок (📍) из текстов;
  отсекаются погода, исторические даты и сообщения о уже случившемся;
* **Сюжетные кластеры 72 ч** — TF-IDF + метод лидера, без словаря; кластеры с низким
  покрытием словарём помечаются «⚠️ вне словаря» — сигнал добавить новую тему в config;
* **Тон повестки** — лексиконная оценка −1…+1 (день, ряд 14 дней, разрез рубрик);
* **Индекс источников** — доля первичных сообщений vs перепечаток (из дедупликации),
  медиана просмотров: «первоисточник / смешанный / перепечатчик»;
* **Прогноз тем на завтра** — наклон ряда + EMA, уверенность по разбросу остатков.

«Инфопространство» считается четырьмя волнами (`build_infospace_ext`, `_w2`, `_w3`, `_w4`
→ `data/infospace.json[w1..w4]` → блоки в `infospace.html`). Волна 4 — метрики на уже
собранной базе, без новых источников: **индекс агентности** (кому поле отдаёт действие:
класс актора × роль, эвристика без морфологического парсера, точность ≈85% по ручной выборке),
**фрейм-карта события** (как один сюжет назван в разных каналах; расхождение фреймов внутри
каскада перепечаток), **ИИ-след** (6 признаков шаблонного производства текста, включая
дословные повторы между источниками) и **устойчивость дедупликации** (пороговый эксперимент
0,30–0,60, сомнительные склейки и контрольная выборка пограничных пар).

* `enrich.py` — доскачивает полные тексты статей со страниц СМИ (JSON-LD `articleBody`,
  скоринг параграфов с отсевом меню/футеров), забирает `og:image` и точную дату публикации.
  Кэш отказов: домены с 403/429/401 пропускаются до следующего дня.
* `dedup.py` — сворачивает перепечатки одного события в кластеры (Жаккар по токенам +
  вложенность заголовков, union-find). В ленте остаётся самый полный материал
  с бейджем «🔁 также сообщили: …». Трекер трендов намеренно считает все записи —
  каскад перепечаток сам по себе сигнал важности темы.

  **Охранные правила** (добавлены 15.09.2026 после того, как метрика «Устойчивость
  дедупликации» в «Инфопространстве» нашла 91 сомнительную склейку — 36% дублей недели):
  * антагонистичные формуляры не склеиваются никогда — «Ракетная опасность» и
    «Снят режим „Ракетная опасность“» это противоположные сообщения, а не перепечатки;
  * служебные формуляры (оповещения о режимах, прогноз погоды) — только в пределах
    `dedup_service_span_h` (6 ч): текст у них идентичен сутки за сутками;
  * обычные материалы — в пределах `dedup_max_span_h` (24 ч; медианная жизнь каскада 1,2–1,6 ч),
    кроме дословных повторов с Жаккаром ≥ `dedup_verbatim_jaccard` (0.85);
  * повтор внутри собственного **издания** склеивается (чистота ленты), но помечается
    `same_source` и не попадает ни в «также сообщили», ни в каскады: первичный материал
    несёт `cluster_src` — число **независимых** изданий, и метрики считают именно его.

  Эффект на неделе: заблокировано 189 склеек, остаточный брак 7 вместо 91,
  оригинальность 82,1% → 85,3%, крупнейший каскад ×20 → ×14 (все независимые).

* `outlets.py` — канонические издания: каналы одной редакции считаются **одним** источником.
  «Улпресса» (RSS `ulpressa.ru`) и `@ulpressa` (Telegram) — это ООО «Симбирск-Паблисити»,
  одна редакция; `@ulgovru` и `@Russkih_Aleksey` — одна пресс-служба исполнительной власти
  области; сайт администрации Ульяновска на Госвебе и `@ulmeria` — одна пресс-служба города.
  Без этого перепечатка своего же релиза в свой же канал выглядела каскадом из «двух
  независимых источников»: 30 из 226 пар «также сообщили» за неделю (13%), а рейтинг
  сеттеров повестки дробился («Улпресса» 28 + «ulpressa» 26 вместо 43 у одного издания).
  Карта — поля `outlet` и `aka` в `sources_registry.json`; объединяются только каналы
  одного производителя (юрлицо/редакция/пресс-служба), конкурирующие каналы одного города
  («Типичный Димитровград» и «Информационный Димитровград» — разные админы) остаются
  разными источниками. Подписи карточек по-прежнему канальные (`src_label`).

## Быстрый старт

```bash
cd gudok
bash run.sh                 # полный цикл: сбор → тренды → генерация
bash run.sh 2026-09-10      # сформировать выпуск за конкретную дату
python3 collector.py --tg-pages 3   # собрать глубже историю Telegram-каналов
```

Нумерация выпусков — от `launch_date` в config.json (11.09.2026 = **№ 0, тестовый**;
12.09.2026 — № 1, первый регулярный). Единая сквозная навигация на всех страницах издания.

Результат: `index.html` (первая полоса), `digests/digest_YYYY-MM-DD.html` (выпуск)
`digests/exec_YYYY-MM-DD.html` (дайджест руководителя — 1 страница A4),
`afisha.html` (афиша культурных событий) и `infospace.html` (сквозное исследование
инфопространства: сеттеры повестки, каскады перепечаток, тон по уровням источников,
федеральное эхо, карта муниципалитетов с зонами информационного молчания, а также
метрики четырёх «волн» расширения — план `infospace-plan.html`: труд и язык,
реестр источников и владельцы, концентрация собственности, агентность и фреймы). Также:
5 событий / 3 риска / 2 решения / сводка трендов, готов к печати в PDF).

## Как получать новости из Telegram простым HTTPS (про te.me / t.me)

Ключевой факт, проверенный на практике:

| Endpoint | Результат |
|---|---|
| `https://te.me/s/<канал>` | ❌ **404** — домен te.me веб-превью не отдаёт (это алиас для сервисных ссылок вида te.me/addstickers/…) |
| `https://t.me/s/<канал>` | ✅ **200** — публичное веб-превью канала, ~20 последних постов, **без авторизации и ключей** |
| `https://t.me/s/<канал>?before=<id>` | ✅ пагинация вглубь истории (по ~20 сообщений за запрос) |

Разметка превью стабильна годами, парсится регулярными выражениями (см. `collector.py → parse_tg_page`):

* сообщение: блок после маркера `tgme_widget_message_wrap`, id — из `data-post="<канал>/<id>"`;
* текст: `<div class="tgme_widget_message_text" ...>` (внутри — только инлайн-теги, `<br>` → перевод строки);
* дата: `<time datetime="2026-09-11T05:34:30+00:00">`;
* просмотры: `<span class="tgme_widget_message_views">12.3K</span>` → «рейтинг вовлечённости» повестки;
* постоянная ссылка поста: `https://t.me/<канал>/<id>`.

**Правила вежливости** (зашиты в collector.py): задержка 1.2 c между запросами, один ретрай,
честный User-Agent, глубина истории ограничена (`tg_history_pages` в config.json).
При агрессивном скрейпинге Telegram может временно ограничить IP.

**Ограничения метода и пути развития:**

1. Превью есть только у **публичных** каналов; закрытые недоступны.
2. Одна страница ≈ 20 постов; для архива на месяцы вперёд лучше взять MTProto-клиент
   (`pip install telethon`, пользовательская сессия, `iter_messages`) — официальнее и полнее.
3. Альтернатива без кода: RSS-мосты (RSSHub: `/telegram/channel/<name>`), но это зависимость от чужого сервиса.
4. Для **новых** постов в реальном времени (а не истории) можно завести бота (Bot API),
   добавить его админом в свой канал и получать `channel_post`-обновления — но для чужих каналов история недоступна,
   поэтому наш сценарий «t.me/s + ?before» — оптимальный простой HTTPS-путь.

В мониторинге **41 активный источник**: 33 Telegram-канала (каталог
[tgstat.ru/tag/ulyanovsk-region](https://tgstat.ru/tag/ulyanovsk-region), 33/33 проверены на доступность
`t.me/s` 11.09.2026), 6 RSS-лент (в т.ч. 4 районные газеты — Карсун, Старая Кулатка «Кумәк көч»,
Новая Малыкла «Звезда», Кузоватово; подключены 15.09.2026 по черновику `district_sources_draft.md`),
1 сообщество VK и **1 сайт органа власти** — `ulmeria.gosuslugi.ru` (администрация Ульяновска).
Ещё 8 TG-каналов и 2 RSS лежат в config с `enabled: false` — включаются одним флагом.

### Сайты муниципалитетов без RSS (Госвеб/NetCat)

Официальные сайты ОМСУ на платформе Госвеб (`*.gosuslugi.ru`) RSS не отдают, но список новостей
рендерится на сервере и размечен микроформатом **schema.org/NewsArticle** — парсится регулярными
выражениями (`collector.py → parse_gosweb_news`):

| Поле | Откуда берём |
|---|---|
| точная дата и время | `<meta itemprop='datePublished' content='2026-09-15 16:04:27'>` (время местное, UTC+4 → переводим в UTC) |
| заголовок и ссылка | `<h2 itemprop="headline"><a href itemprop='url'>` |
| анонс | `<div itemprop="description">` (полный текст досбирает `enrich.py`) |
| рубрики сайта | `<span class='item-category'>` → поле `web_cats` (сравнение с нашей классификацией) |
| фото | `<img src='/netcat_files/…'>` → `photo` (дальше `photos.py`) |

Ограничение платформы: пагинация только JS, поэтому за один запрос доступны ~10 свежих материалов
(как веб-превью `t.me/s`) — истории вглубь нет. Вежливость та же: `http_delay_sec`, честный
User-Agent, `robots.txt` открыт. Добавить ещё один сайт — одна запись в `config.json → web_sources`
(`name`, `url`, `platform: "gosweb"`, `tier`, `territory`) и атрибуты в `seed_sources_registry.py`.
Тип записи в базе — `source_type: "web"`; в реестре источников — `web:<имя>`.
Иерархия доверия (поле `tier` в config.json):

| Tier | Кто это | Примеры |
|---|---|---|
| **1 — официальные/СМИ** | губернатор, правительство, глава города, госСМИ, заводы, клубы, депутаты ГД | `@Russkih_Aleksey`, `@ulgovru`, `@A_Boldakin`, `@ulpressa`, `@ulpravda`, `@reporter73`, `@UAZ_Today`, `@fcvolga`, `@sergeymorozov73`, `@vmkononov` |
| **2 — агрегаторы** | крупные новостные каналы, высокая скорость, возможен кликбейт | `@tresh_ulyan` (145K), `@insaid173` (139K), `@chpulsk` (83K), `@dimitrovgradonline` (55K), `@topor_ul`, `@ulkoroche`, `@ulyanovsk_smi`, `@chpul`, `@ulsk_on`, `@ulsk_73online`, `@ulsk_driver73`, `@dimitrovgradd` |
| **3 — мнения** | авторская аналитика, сатира, анонимы — только как сигнал повестки, не как факт | `@ulpatriot`, `@shugozhor73`, `@terr73`, `@volkodav73`, `@ulkompr`, `@culturnik`, `@ulpromo` |

Tier влияет на: выбор «первичного» материала при дедупликации перепечаток (tier 1 в приоритете),
ранжирование в hero-блоке выпуска и будущий белый список алертов (Фаза 3 — только tier 1).
Ещё 10 каналов лежат в config с `enabled: false` — включаются одним флагом.

⚠️ Осторожно с юзернеймами: `@media73` в Telegram занят посторонним каналом («Медиа футбол»),
`@ulgrad` переименован и мёртв с 2023 — сайт ulgrad.ru при этом жив (RSS работает).
Перед добавлением канала проверяйте его через `https://t.me/s/<username>`.

## Алерт-монитор угроз (alert_monitor.py)

Опрашивает белый список tier-1 каналов (губернатор, правительство, УЛПРЕССА, Репортёр73,
ЧП Ульяновск, глава города) и ищет сообщения о ракетной/беспилотной опасности, сиренах,
атаках БПЛА. Отбой («Снят режим…») закрывает активный алерт. Проверено на истории
10–11.09.2026: **17 истинных срабатываний, 0 ложных**.

```bash
python3 alert_monitor.py --once     # одна проверка (для cron: * * * * *)
python3 alert_monitor.py --loop     # непрерывный мониторинг, интервал 60 с
python3 alert_monitor.py --status   # активные/закрытые алерты
```

Уведомления MVP: консоль + звонок терминала, `data/alerts.log`, `data/alerts.json`
(генератор выпуска показывает красный баннер при активном алерте), `notify-send`/`osascript`
на десктопе. Первый запуск инициализируется без ретро-алертов.
⚠️ Для интервала 60 с нужен локальный процесс (`--loop`, systemd) или cron `* * * * *`;
GitHub Actions подходит только как резерв (минимальный schedule — 5 минут).

## Переклассификация (reclassify.py)

Правили словари рубрик/тем в `config.json`? Переразметьте всю базу без повторного сбора:

```bash
python3 reclassify.py --audit 100   # применить + напечатать выборку для ручного аудита
```

Точность классификации: аудит выборки 100 записей (11.09.2026) — было ~65% чистых
попаданий (first-match), стало ~90% после перехода на скоринг совпадений и правки
словарей (морфология «суд/судья», «задержан/задержали», удаление «ран»→«трансляция»,
«цен[ыа]»→«сцена» и др.). Остаток — эмодзи-лайвы футбольных матчей и гибридные сюжеты.

## Афиша культурных событий (afisha.html)

Отдельная страница, обновляется каждым прогоном: события извлекаются из текстов всех
источников (analytics.py → extract_calendar_full), классифицируются по типам
(🎪 фестивали / 🎭 театр / 🎵 концерты / 🖼 выставки / 👶 детям / 🎬 кино / 🏃 спорт / 🤝 город и встречи / 📌 прочее),
группируются с фильтрами «Сегодня / Завтра / Выходные / 7 дней / Вечером», по типу, гео,
цене и возрасту (клиентский JS; без JS видна вся серверная группировка по дням).
Деловые поездки, политика, инфраструктура и события в других городах отсекаются.
Плюс лента анонсов культурных каналов: @culturnik, @ulpromo, @ProNovosty73.

**Порог входа** (Спринт 3, настройки — `config.json → settings.afisha`): событие проходит,
если есть дата в горизонте 45 дней, время (или «весь день»/«уточняется»), площадка и тип
события, а индекс уверенности не ниже `threshold` (0.55). Порог применяется к **кластеру**
анонсов, а не к отдельной записи: у перепечатки может не быть площадки, хотя у первоисточника
она есть, — свидетельства сливаются, в карточке появляется «также анонсировали: N изд.».

Площадка берётся из четырёх источников по убыванию надёжности: маркер `📍` в посте → имя из
справочника `data/venues.json` в кавычках → то же имя в тексте **без маркера** (`venue_from_text`:
сопоставление по набору основ в любом падеже и порядке слов, с охранами от «современные языковые
модели» ≠ ДК «Современник» и «Главный старт» ≠ стадион «Старт»; улица из адреса различает два
«Современника») → адрес («Адрес: Гончарова, 25»). Фестиваль, ярмарка и кросс, у которых площадок
несколько, идут как «площадки города» с пометкой «площадка уточняется» и половиной кредита
уверенности. Названия событий описательные (`compose_event_title`): «Концерт группы «Мураками»»,
«Матч «Волга» — «Спартак»», «Эндуро-гонка «Слободская балка»» — вместо голого имени из кавычек.

Отсев виден читателю: блок «Не прошло порог» с причиной по каждой записи и блок
«Площадки-кандидаты» — названия из текстов, которых нет в справочнике (редактору на пополнение
`data/venues.json`). Паспорт в шапке: найдено дат → прошло порог → показано сегодня.

## Дизайн-система v2

Газетная вёрстка: антиква для заголовков и лидов, тело 16.5px, палитра «бумага и чернила» с одним
акцентом; тёмная тема — тёплая тёмная бумага. Семантика (<main>/<article>/<time>), skip-link,
prefers-reduced-motion, focus-visible, контраст ≥4.5:1. Мобильная навигация: гамбургер + поиск
по выпуску (встроенный манифест последних 120 заголовков). Алгоритмические метрики (тон повестки и др.)
живут в «Инфопространстве» и месячных отчётах, не на первой полосе.

## Планы и методы (plans.html)

Одна генерируемая страница вместо нескольких рукописных планов: план развития издания
(`ROADMAP.md`), план расширения «Инфопространства» (реестр из 32 метрик-кандидатов и паспорта),
переезд на выделенный сервер (`server_plan.md`) и спринты первой полосы (`plan_frontpage_v4.md`).
Документы перечитываются при каждой сборке (`plans.py`), поэтому страница не разъезжается
с источниками: открытые пункты, этапы миграции и статусы спринтов берутся из markdown, а реестр
метрик, волны внедрения, источники данных и методологические риски — из редакционных данных
`plans.py`. Раздел «Внедрение методов» описывает конвейер из пяти шагов — **паспорт метрики →
данные → расчёт → блок на витрине → тест** — с якорями в коде; правило редакции: метрика
добавляется в раздел только через паспорт. Ссылки на страницу: карточка в «Проектах», вводная
строка и бейджи «Инфопространства», подвал всех страниц («Служебное»).

## Методы исследования инфополя (methods.html)

Реестр методик v1.1 — 36 паспортов (М-01…М-36) в восьми группах: сбор и мониторинг,
текстовый анализ, сети и динамика, проверка и противодействие, экономика и власть,
аудитория и активность, исторический контекст, представление. Плюс сквозной раздел
«Идеология и гегемония» (7 методик: фреймы, голоса, собственность, умолчания, язык,
монополизация поля, самопроверка). Статусы честные: 11 работают, 13 в тестировании,
12 в очереди.

У каждой методики шесть полей паспорта: **вход**, **выход**, **метрики качества**,
**модуль платформы**, **неопределённость** (интервал Уилсона 95% или явная оговорка
для детерминированных и качественных процедур) и **порядок проверки** на контрольной
выборке из архива. Стенд испытания формирует протокол по паспорту (на странице —
кнопкой, в коде — `methods.py → protocol()`, покрыт тестами: бумажный протокол и стенд
не разъедутся). Критерий приёмки: порог ≥ 0.80 с учётом доверительного интервала,
воспроизводимость повторного прогона, выгрузка и запись в методологический журнал (М-28).

Данные — редакционные (`methods.py`), страница генерируется `render_methods()`.
Техконтур описан открытыми стандартами (RFC 9110–9114, RSS 2.0, Atom, JSON Feed,
RFC 4180, ISO 8601, WCAG 2.1 и др.) с явной оговоркой: **ядро конвейера — только
stdlib Python**, перечисленные библиотеки — целевой контур методик, подключаются
через guarded import по решению редакции.

## Тёмная тема

Все страницы (выпуск, витрина, роадмап, спецвыпуски) поддерживают переключатель 🌙/☀️ в шапке.
По умолчанию тема берётся из настроек ОС (`prefers-color-scheme`), выбор запоминается в
localStorage. При печати в PDF автоматически форсируется светлая тема.

## Колонка редактора (LLM-слой без внешних API)

По решению заказчика внешние LLM API не используются — нарративный слой пишет ассистент в чате:

1. Ассистент создаёт `data/editorial_YYYY-MM-DD.md` (простая разметка: абзацы через пустую
   строку, списки через `- `, жирный через `**…**`).
2. `generate.py` подхватывает файл и рендерит секцию «✍️ Колонка редактора» в выпуске за эту дату.
3. Без файла секция просто не выводится — конвейер полностью автономен.

## Трекер тенденций повестки (trends.py)

* **Темы** — словарь из ~17 тематических кластеров в `config.json` (выборы, БПЛА, бюджет, УАЗ, урожай…);
  каждая новость матчится регулярными паттернами, тем может быть несколько.
* **Ряды** — ежедневные счётчики за 14 дней (искры-спарклайны в выпусках).
* **Статусы**: 🔥 растёт (последние 3 дня ≥ ×1.6 к недельной базе), 🆕 новая (раньше не встречалась),
  📉 спадает (−50%), ⚖️ стабильно, 💤 тишина.
* **Вовлечённость** — топ Telegram-постов по просмотрам за 7 дней (что реально читает аудитория,
  а не что активно публикуют СМИ — два разных среза повестки).
* **Прогноз повестки** — автоматические выводы в конце каждого выпуска.

## Регулярный выпуск — 3 способа

### 1. cron на своём сервере/компьютере

```cron
# crontab -e   (07:30 по Ульяновску ежедневно)
CRON_TZ=Europe/Ulyanovsk
30 7 * * * cd ~/gudok && bash run.sh >> data/cron.log 2>&1
```

### 2. GitHub Actions (бесплатно, без сервера)

Загрузите содержимое проекта в репозиторий `gudok` — workflow `.github/workflows/daily.yml` уже настроен:
ежедневно в 07:30 (UTC+4) собирает выпуск, коммитит `data/`, `digests/`, `index.html`
и публикует сайт через GitHub Pages. Есть и ручной запуск (кнопка *Run workflow*).
Отдельные воркфлоу: `weekly.yml` (скелет недельника, понедельник 08:00 UTC+4) и
`monthly.yml` (отчёт за месяц, 1-е число 09:00 UTC+4); все три стоят в общей очереди
`concurrency: gudok-pipeline`.

Коммит и публикацию делает `ci_push.sh` — он закрывает гонку с ручным push
(кейс 15.09.2026: прогон упал на `git push … (fetch first)`, Pages не обновился):
`fetch` → `rebase` поверх свежего `main` → при конфликте пересборка конвейера
на состоянии `origin/main` (чужие данные и код не теряются) → `push` с несколькими
попытками. Команда пересборки задаётся переменной `REBUILD_CMD` в каждом воркфлоу.

### 3. В чате с ассистентом

Просто напишите: *«обнови дайджест»*, *«собери выпуск за вчера»*, *«добавь канал @… в мониторинг»*,
*«почему выросла тема БПЛА?»* — конвейер будет запущен, а сверху добавлена ручная аналитика.

## Настройка (config.json)

* `rss_sources` / `telegram_channels` — добавить/отключить источник (`enabled: false`);
* `categories` — рубрики ленты и их ключевые слова (порядок = приоритет классификации);
* `topics` — темы трекера трендов;
* `settings.tg_history_pages` — глубина чтения Telegram (1 стр ≈ 20 постов);
* `settings.digest_window_hours` — окно выборки материалов в выпуск (по умолчанию 26 ч).

После правки config.json перезапустите `bash run.sh`. Переклассифицировать уже собранную базу
не нужно: классификация применяется при сборе; для полного пересчёта удалите `data/store.jsonl`
и заново выполните `python3 seed_data.py && bash run.sh`.

## Примечания

* Часовой пояс всей системы — UTC+4 (Europe/Ulyanovsk), в базе даты хранятся в UTC.
* Дедупликация — по хэшу URL/заголовка, повторные запуски безопасны.
* HTML автономный: inline CSS/JS/SVG, без CDN — открывается офлайн, печатается в PDF.
* Юридически: собираются только публично доступные материалы; при цитировании сохраняются
  ссылки на первоисточники. Соблюдайте ToS Telegram и не превышайте разумную частоту запросов.
