# Гудок — информационно-аналитический листок марксистской группы «Победа» по Ульяновской области

**🌐 Сайт: https://volgin1917.github.io/gudok/** · обновляется автоматически ежедневно в 07:30 (UTC+4) через GitHub Actions

Автоматизированный конвейер ежедневных дайджестов с трекером тенденций
информационной повестки. **Только стандартная библиотека Python 3.8+ — никаких зависимостей.**

```
сбор (RSS+TG) → обогащение статей → дедупликация → тренды → HTML-выпуск + витрина
  collector.py      enrich.py          dedup.py   trends.py+analytics   generate.py
```

Фаза 2 (`analytics.py`, вызывается автоматически из `trends.py` → `data/analytics.json`):
* **Автоафиша** — извлечение дат, диапазонов, времени и площадок (📍) из текстов;
  отсекаются погода, исторические даты и сообщения о уже случившемся;
* **Сюжетные кластеры 72 ч** — TF-IDF + метод лидера, без словаря; кластеры с низким
  покрытием словарём помечаются «⚠️ вне словаря» — сигнал добавить новую тему в config;
* **Тон повестки** — лексиконная оценка −1…+1 (день, ряд 14 дней, разрез рубрик);
* **Индекс источников** — доля первичных сообщений vs перепечаток (из дедупликации),
  медиана просмотров: «первоисточник / смешанный / перепечатчик»;
* **Прогноз тем на завтра** — наклон ряда + EMA, уверенность по разбросу остатков.

* `enrich.py` — доскачивает полные тексты статей со страниц СМИ (JSON-LD `articleBody`,
  скоринг параграфов с отсевом меню/футеров), забирает `og:image` и точную дату публикации.
  Кэш отказов: домены с 403/429/401 пропускаются до следующего дня.
* `dedup.py` — сворачивает перепечатки одного события в кластеры (Жаккар по токенам +
  вложенность заголовков, union-find). В ленте остаётся самый полный материал
  с бейджем «🔁 также сообщили: …». Трекер трендов намеренно считает все записи —
  каскад перепечаток сам по себе сигнал важности темы.

## Быстрый старт

```bash
cd gudok
bash run.sh                 # полный цикл: сбор → тренды → генерация
bash run.sh 2026-09-10      # сформировать выпуск за конкретную дату
python3 collector.py --tg-pages 3   # собрать глубже историю Telegram-каналов
```

Нумерация выпусков — от `launch_date` в config.json (11.09.2026 = **№ 0, тестовый**;
12.09.2026 — № 1, первый регулярный). Единая сквозная навигация на всех страницах издания.

Результат: `index.html` (первая полоса), `digests/digest_YYYY-MM-DD.html` (выпуск)
`digests/exec_YYYY-MM-DD.html` (дайджест руководителя — 1 страница A4),
`afisha.html` (афиша культурных событий) и `infospace.html` (сквозное исследование
инфопространства: сеттеры повестки, каскады перепечаток, тон по уровням источников,
федеральное эхо, карта муниципалитетов с зонами информационного молчания). Также:
5 событий / 3 риска / 2 решения / сводка трендов, готов к печати в PDF).

## Как получать новости из Telegram простым HTTPS (про te.me / t.me)

Ключевой факт, проверенный на практике:

| Endpoint | Результат |
|---|---|
| `https://te.me/s/<канал>` | ❌ **404** — домен te.me веб-превью не отдаёт (это алиас для сервисных ссылок вида te.me/addstickers/…) |
| `https://t.me/s/<канал>` | ✅ **200** — публичное веб-превью канала, ~20 последних постов, **без авторизации и ключей** |
| `https://t.me/s/<канал>?before=<id>` | ✅ пагинация вглубь истории (по ~20 сообщений за запрос) |

Разметка превью стабильна годами, парсится регулярными выражениями (см. `collector.py → parse_tg_page`):

* сообщение: блок после маркера `tgme_widget_message_wrap`, id — из `data-post="<канал>/<id>"`;
* текст: `<div class="tgme_widget_message_text" ...>` (внутри — только инлайн-теги, `<br>` → перевод строки);
* дата: `<time datetime="2026-09-11T05:34:30+00:00">`;
* просмотры: `<span class="tgme_widget_message_views">12.3K</span>` → «рейтинг вовлечённости» повестки;
* постоянная ссылка поста: `https://t.me/<канал>/<id>`.

**Правила вежливости** (зашиты в collector.py): задержка 1.2 c между запросами, один ретрай,
честный User-Agent, глубина истории ограничена (`tg_history_pages` в config.json).
При агрессивном скрейпинге Telegram может временно ограничить IP.

**Ограничения метода и пути развития:**

1. Превью есть только у **публичных** каналов; закрытые недоступны.
2. Одна страница ≈ 20 постов; для архива на месяцы вперёд лучше взять MTProto-клиент
   (`pip install telethon`, пользовательская сессия, `iter_messages`) — официальнее и полнее.
3. Альтернатива без кода: RSS-мосты (RSSHub: `/telegram/channel/<name>`), но это зависимость от чужого сервиса.
4. Для **новых** постов в реальном времени (а не истории) можно завести бота (Bot API),
   добавить его админом в свой канал и получать `channel_post`-обновления — но для чужих каналов история недоступна,
   поэтому наш сценарий «t.me/s + ?before» — оптимальный простой HTTPS-путь.

Каналы региона в мониторинге — **29 активных** (каталог: [tgstat.ru/tag/ulyanovsk-region](https://tgstat.ru/tag/ulyanovsk-region),
все 33 проверены на доступность `t.me/s` 11.09.2026 — 33/33 OK). Иерархия доверия (поле `tier` в config.json):

| Tier | Кто это | Примеры |
|---|---|---|
| **1 — официальные/СМИ** | губернатор, правительство, глава города, госСМИ, заводы, клубы, депутаты ГД | `@Russkih_Aleksey`, `@ulgovru`, `@A_Boldakin`, `@ulpressa`, `@ulpravda`, `@reporter73`, `@UAZ_Today`, `@fcvolga`, `@sergeymorozov73`, `@vmkononov` |

## Алерт-монитор угроз (alert_monitor.py)

Опрашивает белый список tier-1 каналов (губернатор, правительство, УЛПРЕССА, Репортёр73,
ЧП Ульяновск, глава города) и ищет сообщения о ракетной/беспилотной опасности, сиренах,
атаках БПЛА. Отбой («Снят режим…») закрывает активный алерт. Проверено на истории
10–11.09.2026: **17 истинных срабатываний, 0 ложных**.

```bash
python3 alert_monitor.py --once     # одна проверка (для cron: * * * * *)
python3 alert_monitor.py --loop     # непрерывный мониторинг, интервал 60 с
python3 alert_monitor.py --status   # активные/закрытые алерты
```

Уведомления MVP: консоль + звонок терминала, `data/alerts.log`, `data/alerts.json`
(генератор выпуска показывает красный баннер при активном алерте), `notify-send`/`osascript`
на десктопе. Первый запуск инициализируется без ретро-алертов.
⚠️ Для интервала 60 с нужен локальный процесс (`--loop`, systemd) или cron `* * * * *`;
GitHub Actions подходит только как резерв (минимальный schedule — 5 минут).

## Переклассификация (reclassify.py)

Правили словари рубрик/тем в `config.json`? Переразметьте всю базу без повторного сбора:

```bash
python3 reclassify.py --audit 100   # применить + напечатать выборку для ручного аудита
```

Точность классификации: аудит выборки 100 записей (11.09.2026) — было ~65% чистых
попаданий (first-match), стало ~90% после перехода на скоринг совпадений и правки
словарей (морфология «суд/судья», «задержан/задержали», удаление «ран»→«трансляция»,
«цен[ыа]»→«сцена» и др.). Остаток — эмодзи-лайвы футбольных матчей и гибридные сюжеты.

## Афиша культурных событий (afisha.html)

Отдельная страница, обновляется каждым прогоном: события извлекаются из текстов всех
источников (analytics.py → extract_calendar), классифицируются по типам
(🎪 фестивали / 🎭 театр / 🎵 концерты / 🖼 выставки / 👶 детям / 🎬 кино / 🏃 спорт / 📌 прочее),
группируются с фильтрами «Сегодня / Завтра / Выходные / 7 дней» (клиентский JS).
Деловые поездки, политика, инфраструктура и события в других городах отсекаются.
Плюс лента анонсов культурных каналов: @culturnik, @ulpromo, @ProNovosty73.

## Тёмная тема

Все страницы (выпуск, витрина, роадмап, спецвыпуски) поддерживают переключатель 🌙/☀️ в шапке.
По умолчанию тема берётся из настроек ОС (`prefers-color-scheme`), выбор запоминается в
localStorage. При печати в PDF автоматически форсируется светлая тема.

## Колонка редактора (LLM-слой без внешних API)

По решению заказчика внешние LLM API не используются — нарративный слой пишет ассистент в чате:

1. Ассистент создаёт `data/editorial_YYYY-MM-DD.md` (простая разметка: абзацы через пустую
   строку, списки через `- `, жирный через `**…**`).
2. `generate.py` подхватывает файл и рендерит секцию «✍️ Колонка редактора» в выпуске за эту дату.
3. Без файла секция просто не выводится — конвейер полностью автономен.

## Трекер тенденций повестки (trends.py)

* **Темы** — словарь из ~17 тематических кластеров в `config.json` (выборы, БПЛА, бюджет, УАЗ, урожай…);
  каждая новость матчится регулярными паттернами, тем может быть несколько.
* **Ряды** — ежедневные счётчики за 14 дней (искры-спарклайны в выпусках).
* **Статусы**: 🔥 растёт (последние 3 дня ≥ ×1.6 к недельной базе), 🆕 новая (раньше не встречалась),
  📉 спадает (−50%), ⚖️ стабильно, 💤 тишина.
* **Вовлечённость** — топ Telegram-постов по просмотрам за 7 дней (что реально читает аудитория,
  а не что активно публикуют СМИ — два разных среза повестки).
* **Прогноз повестки** — автоматические выводы в конце каждого выпуска.

## Регулярный выпуск — 3 способа

### 1. cron на своём сервере/компьютере

```cron
# crontab -e   (07:30 по Ульяновску ежедневно)
CRON_TZ=Europe/Ulyanovsk
30 7 * * * cd ~/gudok && bash run.sh >> data/cron.log 2>&1
```

### 2. GitHub Actions (бесплатно, без сервера)

Загрузите содержимое проекта в репозиторий `gudok` — workflow `.github/workflows/digest.yml` уже настроен:
ежедневно в 07:30 (UTC+4) собирает выпуск, коммитит `data/`, `digests/`, `index.html`
и (опционально) публикует сайт через GitHub Pages. Есть и ручной запуск (кнопка *Run workflow*).

### 3. В чате с ассистентом

Просто напишите: *«обнови дайджест»*, *«собери выпуск за вчера»*, *«добавь канал @… в мониторинг»*,
*«почему выросла тема БПЛА?»* — конвейер будет запущен, а сверху добавлена ручная аналитика.

## Настройка (config.json)

* `rss_sources` / `telegram_channels` — добавить/отключить источник (`enabled: false`);
* `categories` — рубрики ленты и их ключевые слова (порядок = приоритет классификации);
* `topics` — темы трекера трендов;
* `settings.tg_history_pages` — глубина чтения Telegram (1 стр ≈ 20 постов);
* `settings.digest_window_hours` — окно выборки материалов в выпуск (по умолчанию 26 ч).

После правки config.json перезапустите `bash run.sh`. Переклассифицировать уже собранную базу
не нужно: классификация применяется при сборе; для полного пересчёта удалите `data/store.jsonl`
и заново выполните `python3 seed_data.py && bash run.sh`.

## Примечания

* Часовой пояс всей системы — UTC+4 (Europe/Ulyanovsk), в базе даты хранятся в UTC.
* Дедупликация — по хэшу URL/заголовка, повторные запуски безопасны.
* HTML автономный: inline CSS/JS/SVG, без CDN — открывается офлайн, печатается в PDF.
* Юридически: собираются только публично доступные материалы; при цитировании сохраняются
  ссылки на первоисточники. Соблюдайте ToS Telegram и не превышайте разумную частоту запросов.
