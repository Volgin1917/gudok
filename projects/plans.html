Внедрение методов

паспорт → данные → расчёт → блок → тест
Правило редакции: метрика или методика добавляется в раздел только через паспорт — с гипотезой, формулой, источником данных, порогом тревоги и местом публикации. Пять шагов ниже одинаковы для метрик «Инфопространства», для порогов афиши и для правил дедупликации: отличается только файл.
1

Паспорт метрики

Гипотеза, формула, источник данных, порог тревоги, где публикуется и первый иллюстративный расчёт. Шесть полей паспорта — без них метрика в реестр не попадает.

Где в коде: plans.py → PILOTS (пилоты), REG (реестр из 32 кандидатов)
Проверка: решение редакции на планёрке; паспорт виден на странице «Планы»
Пример — TLI: гипотеза «труд присутствует как объект, но не как субъект речи», порог тревоги TLI < 0.10 неделю подряд
2

Данные

Что нужно для расчёта: уже собранная база, реестр источников, словари config.json или внешняя выгрузка. Пока источника нет, метрика живёт в статусе «ищем данные».

Где в коде: data/store.jsonl · sources_registry.json · config.json · data/goszakupki_eis.csv
Проверка: источник назван в паспорте и доступен конвейеру без сторонних зависимостей
Пример — TLI: store.jsonl (1405 сообщений за 7 дней) + маркер-словарь профессий
3

Расчёт

Функция в analytics.py пишет метрику в data/infospace.json в разрезе своей волны (w1–w4). Считаем только на stdlib: эвристики и словари вместо внешних API.

Где в коде: analytics.py: build_infospace · build_infospace_ext (w1) · build_infospace_w2/w3/w4 · compute_eis_metrics
Проверка: python3 analytics.py пересобирает data/infospace.json из текущей базы
Пример — TLI: build_infospace_ext → infospace.json[w1].tli (шесть групп, доля субъектности)
4

Блок на витрине

render_infospace() собирает блок: число, подпись, развертка и методика под блоком. Вёрстка самодостаточная (inline CSS/SVG), страница открывается офлайн и печатается.

Где в коде: generate.py: render_infospace (w1–w4), infospace.html
Проверка: блок виден без JavaScript, числа сходятся с data/infospace.json
Пример — TLI: шесть полос bar-row по группам + значение индекса (9% — «труд невидим»)
5

Тест и статус

Юнит-тест на расчёт и на присутствие блока на странице. После зелёного прогона метрика получает статус «подключена» с датой, запись уходит в ROADMAP.md.

Где в коде: tests/test_pipeline.py: TestInfospaceW1–W4 · TestEisMetrics · TestSourcesRegistry · TestOutlets
Проверка: python3 -m unittest discover -s tests — зелёный до публикации
Пример — TLI: подключена 15.09 (Волна 1), поле dn в реестре, запись в версии документа

Паспорта метрик-пилотов

3 паспорта · образец для остальных
Индекс присутствия труда (TLI)
готовы ось: Труд трудозатраты: S–M

Проверяет гипотезу: в региональном инфополе труд существует как объект — в сводках ЧП, отчётах о посещении завода, поздравлениях с праздником — и почти никогда как субъект речи.

Гипотеза
Рабочие УАЗа, Авиастара, УМЗ, учителя и медики области присутствуют в повестке, но не говорят от своего имени. Если это так, доля «оригинальных» сообщений ничего не говорит о реальном плюрализме поля.
Формула
TLI = (S_субъект − S_объект) / S_всего, где S — сообщения с маркерами шести групп:
рабочие и инженеры · учителя · медики · водители и транспортники · селяне · студенты

TLI < 0.15 → «труд невидим»; 0.15–0.35 → «труд упоминаем»; > 0.35 → «труд говорит»
Источник данных
store.jsonl (уже собрано: 1405 сообщений за 7 дней). Дополнительно: маркер-словарь профессий и детекция прямой речи (кавычки + атрибуция).
Порог тревоги
Порог тревоги: TLI &lt; 0.10 неделю подряд — фиксируется как структурный перекос, а не случайность недели.
Где публикуется
Блок в разделе «Инфопространство» рядом с «Оригинальностью по уровням»: шесть полос bar-row по группам + значение индекса. В недельнике — сравнение с прошлой неделей.
Первый расчёт
Иллюстративный расчёт на текущей базе: из 1405 сообщений профессиональные группы упомянуты в ~90; в роли подлежащего — в ~12. TLI ≈ 0.03.
Деньги повестки
ищем данные ось: Собственность трудозатраты: M–L

Связывает публичные госконтракты на информационное освещение с реальным содержанием поля: кто заказчик, кто подрядчик, какая сумма и какой тон сообщений подрядчика.

Гипотеза
Значимая доля сообщений, которые дедупликатор считает оригинальными, производится по контракту или из пресс-служб. Без этого метрика «82% оригинальных» описывает форму, а не самостоятельность редакций.
Формула
MoneyShare = Σ(сообщения подрядчика за период) / Σ(все сообщения)
TonePaid − ToneIndep = разница лексиконной тональности
Rub/Msg = сумма контракта / число сообщений подрядчика за период
Источник данных
ЕИС zakupki.gov.ru (открытый API по заказчикам региона), реестр СМИ Роскомнадзора, ЕГРЮЛ для учредителей; сопоставление подрядчика с sources_registry.json.
Порог тревоги
Порог: MoneyShare &gt; 25% или TonePaid − ToneIndep &gt; 0.20 — повод для разбора в недельнике.
Где публикуется
Таблица tbl: заказчик → исполнитель → сумма → сообщений/нед → тон → доля в повестке. Рядом bar-row «кто оплачивает освещение» и примечание о неполноте данных (не все контракты публичны).
Первый расчёт
Первый шаг без ЕИС: помечать сообщения пресс-служб (ulgovru, администрация, министерства) как «официально-оплаченный слой» и считать его долю — это уже Волна 1.
Латентность и скорость каскада
готовы ось: Время трудозатраты: S

Превращает «Каскады недели» из статичного списка в процесс с временем: сколько часов поле догоняет событие и как быстро сюжет доходит до ×5 источников.

Гипотеза
Инфополе региона запаздывает на 2–6 часов, причём тревожные сюжеты (режим «Беспилотная опасность», ДТП, суды) расходятся втрое быстрее позитивных. Это проверяемо на уже собранных timestamp.
Формула
Δt = t_первой публикации − t_события (из текста; fallback — время поста)
v = число источников / часы до ×5
Decay = часов от пика каскада до последнего подхвата
Источник данных
store.jsonl (timestamp каждого сообщения), кластеры каскадов из dedup.py, темы из классификатора.
Порог тревоги
Порог: медианная Δt &gt; 6 ч по тревожным темам — признак того, что поле не выполняет функцию оперативного оповещения.
Где публикуется
Блок из трёх полос: медиана Δt по темам (ЧП, ЖКХ, власть, культура), скорость каскада по дням, «полка жизни сюжета». Плюс метка времени на каждом каскаде: «×16 за 3 ч 20 мин».
Первый расчёт
Реализуется одним проходом по store.jsonl; метрика уже значится в очереди как «Задержки освещения» — остаётся добавить формулу и пороги.

Методологические риски

что может исказить картину и как это лечим
  • Смещение выборки — Поле = Telegram-каналы + RSS нескольких изданий. Районы, VK, ОК и форумы вне кадра: «покрытие муниципалитетов 100%» означает лишь то, что о каждой территории хоть раз написали областные каналы. Лечение: реестр источников с оценкой полноты и отдельная метрика «аудит выборки».
  • Тональность и ирония — Лексикон на ±110 маркеров не ловит сарказм, эмодзи-иронию и «народную» лексику анонимных каналов. Тон T3 (+0.17) может быть артефактом. Лечение: ручная разметка 200 сообщений, отдельный вес для эмодзи, публикация доверительного интервала.
  • Дедупликация склеивает анонсы — Анонс и итог одного события — разные сообщения, но Жаккар может их объединить: «оригинальность 82%» тогда завышена. Лечение: контроль по кластерам, где временной разрыв больше 24 часов.
  • Граница «федерального эха — СВО-сводки, ключевая ставка и 5G часто имеют региональную привязку (имена, адреса, местные предприятия). Бинарная метка «регион/федералы» спорна. Лечение: трёхуровневая шкала — чисто федеральное, с местной привязкой, местное.
  • Персональные данные в комментариях — Слой аудитории соблазнительно измеряем, но это живые люди. Лечение: хранить только агрегаты, без имён и цитат, обезличивать на этапе сбора, зафиксировать правило в разделе «Методика».
  • Воспроизводимость — store.jsonl растёт, пересчёт старых недель даёт другие цифры. Лечение: снапшоты metrics по неделям (уже есть weekly/ и monthly/), версия методики в штампе каждого блока.
  • Ручной труд и зависимость от одного человека — Районные источники, реестр владельцев, разметка — всё это ручная работа. Лечение: задачи в ROADMAP.md с ответственным и сроком, статус в status.html.
  • Соблазн интерпретации — Цифры вроде «48% федеральное эхо» легко превратить в политический вывод без проверки. Лечение: каждый блок обязан содержать строку методики и порог, выше которого вывод считается обоснованным.

Точки выбора
  • решено — Провайдер и бюджет: РФ-VPS, уровень «Минимум» — 1 vCPU / 2 ГБ RAM + 2 ГБ swap / 40–50 ГБ NVMe, Ubuntu 24.04, ~300–500 ₽/мес (кандидаты: Beget, FirstVDS, Aeza; Timeweb Cloud — если «минимум» окажется сопоставим по цене). LLM-запас не закладываем; при росте — resize 2→4 ГБ у того же провайдера.
  • решено — GitHub Pages: остаётся зеркалом — gh-pages = снапшот последней сборки (force-update раз в сутки, история не растёт), main — только код. Откат при падении VPS — возврат DNS за минуты.
  • решено — Локальный LLM: вне горизонта — эвристики и словари остаются ядром; возврат к вопросу после апгрейда железа или на отдельной машине.

Состав документа

  • Ключевые находки
  • Без изменений (подтверждены ранее)
  • Итог для реестра
  • Издания: каналы одной редакции (15.09.2026, outlets.py)
  • Объединено (основание — один производитель)
  • Не объединено (разные производители, несмотря на схожую тематику)
  • Эффект на данных недели (15.09.2026, 1933 записи)
Историческая справка: до объединения планы жили отдельными страницами — roadmap.html (визуальная версия ROADMAP.md) и infospace-plan.html (черновик предложения v0.9 по расширению «Инфопространства»).
